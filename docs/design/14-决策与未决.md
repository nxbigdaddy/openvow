## 17. 关键决策（ADR）

| # | 决策 | 否决的方案 | 理由 |
| --- | --- | --- | --- |
| 01 | 拉模式（终端 claim） | 推模式 | 风控与成本必须留在终端 |
| 02 | 平台不内置任何模型 | 内置拆解/审查 Agent | 一旦内置，边界破 |
| 03 | Postgres `SKIP LOCKED` | Redis 锁 / Celery / Prefect | 一条 SQL 解决，少一个中间件 |
| 04 | 内容寻址产物库 | 按任务存目录 | 去重、可回溯、防路径绕过 |
| 05 | 拆解也是任务 | 平台内置 planner | 保持不变量 |
| 06 | 接口前置为独占任务 | 靠 `decisions[]` 口头约定 | 文件不相交 ≠ 语义能对接 |
| 07 | 测试独立 + 红测试 + 冻结 | 实现方自带测试 | 否则验收可被自己判卷 |
| 08 | 集成是任务 | 作为流水线阶段 | 失败需要工作载体 |
| 09 | MCP 适配器优先 | 一段 System Prompt | 批处理 CLI 无法定时心跳 |
| 10 | 匿名只在协议层 | 真匿名 | 私有项目需要追责与治理 |
| 11 | 风控叙事降级 | 以"防封号"为核心卖点 | 套利不可持续 |
| 12 | 校验四层，合并是任务 | L0–L4 五层 | 合并需要判断，不能机械化 |
| 13 | 平台只决定顺序，不改字节 | 平台自动修复 | 改字节破坏"零二次加工" |
| 15 | 增加 `explore` 任务类型 | 让用户在平台外自行调研 | 调研是项目开头两成工作，没有位置就会卡住；产出只到"草案"，决策权仍归人 |
| 14 | 不引入奖励 / 代币 / 竞价，采用配额与优先级 | 积分制、竞价、排行榜、Agent reward shaping | 私有场景的痛点是分配不是激励；可交易积分必然被刷；平台无法验证真实 token 消耗 |

## 18. 未决问题

1. **merge group 怎么切？** 默认整图；大图按模块拆多个 group 并行集成，但跨 group 的接口一致性会退化为"组间集成"。需实测阈值。
2. **红测试的 `min_failing_ratio` 定多少？** 0.8 是拍的，有些模块天然一半是类型测试。
3. **repair 的写集要不要放开到全仓？** 放开能修得动，但破坏"写集可控"的直觉。倾向默认放开 + 人工过目。
4. **信任分会不会惩罚慢工出细活？** 一次通过率奖励"稳"，可能抑制"敢重构"。必要时加返工率作第二维。
5. **是否支持从 issue tracker 直接建需求？** 降低门槛，但会把"需求条目化"外包给外部系统。
6. **配额的周期与权重怎么定？** 按周还是按项目结算；`terminal_seconds` 之外要不要把 token 折算进来（自报的数不可信，可能只作为参考列展示）。等真正出现多所有者时用真实数据再定。
